本文记录在一台老卡服务器（3× Tesla V100-SXM2-16GB，驱动 525.125.06）上，用 conda 环境部署并运行 BreezeBlue/Breeze-TTS-2 的全过程。

覆盖两种运行方式：命令行推理（infer.py）与流式 HTTP API（python -m breeze_infer.api）。

官方默认配置面向 H100/A100 + CUDA 12.8 + flash-attn，V100 不能照抄。文中所有命令均在本机实测跑通，可以直接抄。

1. Breeze TTS 2 是什么

Breeze TTS 2 是 BreezeBlue 开源的实时中英双语 TTS 模型，在开源 TTS 榜单上排名第一。它的核心能力有四项：

  • 🎙️ 语音克隆（Voice Clone）：给一段参考音频 + 它的准确文字稿，复刻音色、节奏、情感。
  • 🎨 声音设计（Voice Design）：不需要参考音频，只用一句自然语言描述就生成独特音色。
  • 🎛️ 声音指导（Voice Direction）：克隆参考说话人的身份，同时用指令调整语气、情绪、语速。
  • 🎭 拟声事件（Vocal Events）：英文用圆括号如 (laugh) (sigh)，中文用方括号如 [笑] [叹气]。
  • ⚡ 低延迟流式输出：单声道 24kHz 16bit PCM。

⚠️ 许可先看清楚：源码是 Apache-2.0，但模型权重、衍生模型及自托管输出仅限研究与非商业用途（BreezeBlue Research and Non-Commercial License）。详见第 7 节。

3. 避坑指南：V100 与官方默认配置的三处不同（务必先读）

本机是 V100（Volta 架构），和官方默认配置（H100/A100 + CUDA 12.8 + flash-attn）有三处关键差异。这三处如果不知道，几乎必然会卡住；本文档已针对性调整。

3.1 坑一：V100 不支持 flash-attn，必须走 eager 模式

官方 Docker 会单独安装 flash-attn==2.8.3，但这个库只支持 Ampere（sm80）及以上，不支持 V100。

好消息是：官方推理代码 infer.py 和 api.py 默认就是 eager 注意力（代码里硬编码 attn_implementation="eager"），eager 路径完全不依赖 flash-attn。requirements.txt 里本来也没有 flash-attn。

✅ 结论：不安装 flash-attn，直接用默认 eager 模式即可。--fast-all 加速路径在 V100 上不可用（它依赖 flash-attn + CUDA Graph，面向 H100/A100），本文档不使用。

3.2 坑二：必须用 torch cu126，而不是官方的 cu128

PyTorch 官方已经在 CUDA 12.8 / 12.9 的二进制中删除了 Volta（sm70）架构支持，只有 CUDA 12.6（cu126）构建仍保留 sm70（架构列表 5.0;6.0;7.0;7.5;8.0;8.6;9.0）。

✅ 结论：torch / torchaudio 一律安装 2.9.1+cu126。即使将来升级了驱动，V100 也必须用 cu126——cu128 里根本没有 sm70 内核，装上去也跑不起来。

3.3 坑三：驱动 525 与 torch cu126 的兼容性（本机实测通过 ✅）

这是最让人心里没底的一处，逐条说清：

  • torch cu126 = CUDA 12.6，官方要求驱动 ≥ 560.35.03；
  • 本机驱动 525.125.06 只到 CUDA 12.0，低于官方要求；
  • 但 NVIDIA 的「CUDA 小版本兼容」机制允许 CUDA 12.x 应用运行在 ≥ 525.60.13 的驱动上。

本文档已在本机（3× V100 + 驱动 525.125.06）实测通过：torch.cuda.is_available() 返回 True，3 张 V100 均被正确识别，GPU 矩阵运算正常。

⚠️ 这是官方未测试的非标准路径。若换到其它机器，仍建议先做第 4.4 步的冒烟测试确认；万一失败，参考附录 A 升级驱动。

6. 实测结果与性能感受

部署完成后在本机跑了一轮，记录下来供参考：

  • 显存：eager 模式单实例约 7.7 GiB，16GB 的 V100 跑单实例余量充足（还留有空间给参考音频的编解码）。想同时跑 3 个实例，就给每个实例用 CUDA_VISIBLE_DEVICES 绑定单卡，3×16GB 刚好一人一张。
  • 并行策略：3 张 V100 下，用 CUDA_VISIBLE_DEVICES=0/1/2 起三个进程是最省心的并行方式，比单进程内部多卡切分简单得多，也不会互相抢显存。
  • 输出格式：命令行推理直接落 .wav；HTTP API 返回的是 流式单声道 24kHz、16bit 小端 PCM，要落盘成通用音频格式需要过一次 ffmpeg。
  • 速度：V100 上只能用 eager 注意力，--fast-all 那条加速路径（flash-attn + CUDA Graph）用不了，所以别指望和 H100 一样的吞吐。好在 API 是流式返回，首包延迟的实际听感比「等整段合成完」要好。

一句话总结：V100 能跑、够用，但要走「eager + cu126 + 单卡单实例」这条非官方路径，并且接受它比 Ampere/Hopper 慢。

7. 常见问题（FAQ）

Q1：torch.cuda.is_available() 返回 False，或报 driver version is insufficient？
→ 驱动 525 无法运行 cu126。见附录 A 升级驱动到 ≥ 570（升级后仍然用 cu126）。

Q2：安装后 torch 变成了 2.9.1+cu128？
→ 被 PyPI 默认源覆盖了。重新执行 4.3 的 cu126 两步安装命令即可。

Q3：显存不足（OOM）？
→ 保持 eager 模式（默认），不要加 --fast-all。eager 约 7.7 GiB，16GB V100 足够；如果同时跑 3 个实例，请各自用 CUDA_VISIBLE_DEVICES 绑定单卡。

Q4：--cfg-scale 该取多少？
→ 默认 1.0。官方对「声音设计 / 声音指导」建议 --cfg-scale 4，以增强指令跟随。

Q5：pip 装 torch 时反复 Connection interrupted / incomplete-download，或者装到一半 No space left on device？
→ 前者是从 pypi.nvidia.com 拉取 nvidia 大文件被中断，按 4.3 的两步走：torch 用 --no-deps 装，nvidia 依赖改从清华镜像装。
→ 后者是根分区 / 满了（df -h / 查）。pip 默认把下载缓存写到 ~/.cache/pip、临时文件写到 /tmp，都在 / 上。用 4.2 末尾的环境变量把 PIP_CACHE_DIR / TMPDIR 重定向到有空间的分区（如 /mnt），也可以 pip cache purge 清理旧缓存释放空间。
